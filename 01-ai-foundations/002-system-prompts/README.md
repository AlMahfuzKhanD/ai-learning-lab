# Understanding System Prompt vs User Prompt vs Assistant Prompt

## Overview

Every AI conversation is built on a sequence of messages, and each message has a specific role.

Understanding these roles is one of the most important foundations for building AI-powered applications.

Whether you're creating a chatbot, an ERP assistant, or a customer support agent, the AI's behavior depends on how these messages are structured.

The three primary message roles are:

* System Prompt
* User Prompt
* Assistant Prompt (Assistant Message)

---

# The Big Picture

An AI model does not simply receive a single prompt.

Instead, it receives a list of messages.

```text
System Prompt
        ↓
User Prompt
        ↓
Assistant Response
        ↓
User Prompt
        ↓
Assistant Response
        ↓
...
```

Every new request includes the previous conversation (or a selected history), allowing the AI to maintain context.

---

# System Prompt

## Definition

A **System Prompt** defines the AI's identity, behavior, responsibilities, and boundaries.

It answers questions such as:

* Who are you?
* What is your job?
* How should you communicate?
* What should you never do?
* What tools are available?
* When should you use those tools?

Unlike User Prompts, the System Prompt usually remains unchanged throughout the conversation.

---

## Example

```text
You are an ERP AI Assistant.

Always answer professionally.

Never guess business data.

If live information is required, use the appropriate backend tool.

Respond in Markdown.
```

The user never sees these instructions.

They only influence the AI's behavior.

---

## Responsibilities of the System Prompt

* Defines AI identity
* Sets communication style
* Establishes business rules
* Controls response format
* Restricts unwanted behavior
* Instructs when to call external tools

---

# User Prompt

## Definition

The User Prompt is the instruction or question provided by the user.

Unlike the System Prompt, it changes with every interaction.

---

## Examples

```text
Show today's pending deliveries.
```

```text
Generate a sales report.
```

```text
Explain Function Calling.
```

```text
Summarize this document.
```

The User Prompt defines the current task.

---

# Assistant Prompt (Assistant Message)

Although commonly referred to as an "Assistant Prompt," it is actually the AI's previous response.

Every response generated by the model becomes part of the conversation history.

This allows the AI to maintain context across multiple messages.

---

## Example

### User

```text
Show customers with overdue loans.
```

### Assistant

```text
There are 14 customers with overdue loans.
```

### User

```text
Show only those above 100,000 BDT.
```

The second question never mentions "overdue loans."

The AI understands because its previous response is included in the conversation.

---

# How They Work Together

A complete AI conversation looks like this:

```text
System:
You are an ERP Assistant.

↓

User:
Show today's pending deliveries.

↓

Assistant:
There are 23 pending deliveries.

↓

User:
Which customer has the highest quantity?

↓

Assistant:
ABC Textile Ltd has the highest pending quantity.
```

Each message contributes to the overall context.

---

# Laravel Example

When integrating an LLM into Laravel, the application typically sends a message array like this:

```json
[
    {
        "role": "system",
        "content": "You are an ERP Assistant."
    },
    {
        "role": "user",
        "content": "Show overdue customers."
    }
]
```

The AI responds with:

```json
{
    "role": "assistant",
    "content": "There are 14 overdue customers."
}
```

For the next request, the application includes the previous assistant response so that context is preserved.

# ERP Use Cases

## Cold Storage ERP

System Prompt:

```text
You are a Cold Storage ERP Assistant.

Never estimate stock quantities.

Always retrieve live ERP data before answering.

Explain reports in simple language.
```

Possible User Prompt:

```text
Which customers currently have overdue loans?
```

---

## RMG ERP

System Prompt:

```text
You are a Merchandising ERP Assistant.

Never guess shipment dates.

Use available ERP data when answering.
```

Possible User Prompt:

```text
Show all LCs expiring within the next 30 days.
```

---

## F-Commerce

System Prompt:

```text
You are a customer support assistant.

Always be friendly.

Recommend products honestly.

Never promise unavailable stock.
```

Possible User Prompt:

```text
Suggest a summer collection under 3,500 BDT.
```

# Why This Matters

A powerful AI model alone does not guarantee a reliable application.

The quality of the System Prompt determines:

* AI personality
* Business rules
* Response consistency
* Safety
* Reliability

Poor System Prompt:

* Inconsistent responses
* Hallucinated business data
* Unclear communication

Well-designed System Prompt:

* Consistent behavior
* Better user experience
* Reliable business applications

---

# Relationship with Function Calling

Function Calling allows AI to interact with external systems.

The System Prompt tells the AI **when** it should use those functions.

Example:

```text
If the user requests live ERP information, always use the appropriate function instead of guessing.
```

Together, these concepts enable AI assistants to work with real business data instead of generating assumptions.

---

# Key Takeaways

* Every AI conversation is a sequence of messages with different roles.
* The System Prompt defines the AI's identity and behavior.
* The User Prompt defines the current task.
* Assistant Messages preserve conversation context.
* Good System Prompt design is essential for building reliable AI applications.
* These concepts are fundamental for ERP assistants, customer support bots, AI agents, and business automation systems.
